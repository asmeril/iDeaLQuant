## Known Limits

- This is not a crack or licensing bypass.
- Obfuscated names remain obfuscated.
- ILSpy output is best-effort C# and may contain compiler-generated state machines.
- Runtime-only behavior still needs validation inside `ideal.exe`.
- External processes cannot reliably inspect all iDeal in-process state; prefer running diagnostic code inside iDeal and writing results to files.

## Practical Workflow

1. Search `IDEAL_ULTIMATE_GUIDE.md` for documented usage.
2. Search parent `reference/Robot_*.txt`, `reference/Sorgu_*.txt`, `reference/Strateji_*.txt`, `reference/Ornek_*.txt` for working patterns.
3. Search `exe_analysis_current/10_focused_api_report.md` and `11_public_method_index.csv` for internal classes and method signatures.
4. Open the matching decompiled `.cs` file under `ilspy_decompile_current/` only when method body details are necessary.
5. Validate with an iDeal script whenever behavior depends on runtime state, UI grids, broker accounts, or active market data.

## Safety Notes

- Do not send live orders based only on reverse-engineered assumptions.
- Keep dry-run modes and explicit logging.
- Separate real account state from robot-local software state.
- Label data sources in logs: `ViopHesapOku`, `BistHesapOku`, `PozisyonKontrol`, UI grid, or file export.
